# Data model

Derived from the sections above. SQLite / D1 dialect. Money is integer coins; there are no floats anywhere in the economy. Times are UTC ISO-8601; the user's local day is resolved from a stored timezone. Nothing is hard-deleted that a ledger entry points at.

**The three invariants the schema must protect**

1. The wallet balance always equals the sum of the ledger. The balance is never stored as a column; it is the ledger's running total.
2. A sealed album's economic columns never change. Editions are new rows, never mutations.
3. An occurrence's coin snapshot is written once, at completion, and never recomputed.

```sql
-- one row, effectively; user_id exists so a second person is a migration, not a rewrite
user(id, passphrase_hash, timezone, created_at)

epic(id, user_id, title, accent, coin_goal_album_id?, created_at)

-- the routine/one-off DEFINITION. never stores future occurrences.
task(
  id, user_id, epic_id?,
  title, description?, url?,
  effort_minutes, reward_coins,          -- reward defaults to effort, may differ
  priority,                              -- low | medium | high
  type,                                  -- routine | oneoff
  weekdays?,                             -- 7-bit mask, routine only
  starts_on?, ends_on?,                  -- routine bounds, optional
  due_at?,                               -- oneoff only, date+time
  created_at, deleted_at?               -- soft delete; past occurrences survive
)

-- materialized lazily, one per completed-or-touched scheduled day
occurrence(
  id, task_id,
  scheduled_on,                          -- the day it belongs to
  status,                                -- pending | done | missed | archived
  completed_at?,                         -- real timestamp; may differ from scheduled_on
  reward_snapshot_coins?,                -- frozen at completion, never recomputed
  UNIQUE(task_id, scheduled_on)
)

-- the single source of truth for the wallet. append-only.
ledger(
  id, user_id,
  amount_coins,                          -- +earn / -spend / +sale
  reason,                                -- task_reward | album_unlock | sticker_buy
                                         --  | random_pull | duplicate_sale
  occurrence_id?, album_id?, sticker_id?,
  created_at                             -- immutable
)

-- sealed on create. economic columns are write-once.
album(
  id, user_id,
  title, description?, cover_key,        -- cover_key -> R2 object
  derived_from_album_id?,                -- edition chain
  unlock_price, random_price,            -- coins
  price_common, price_rare, price_epic, price_legendary,
  odds_common, odds_rare, odds_epic, odds_legendary,   -- integers, sum = 100
  unlocked_at?, completed_at?,
  sealed_at, created_at
)

-- immutable set, fixed at seal; slot_index is the shuffled print/display order
sticker(
  id, album_id,
  image_key,                             -- -> R2 object (colour master; grayscale is a render filter)
  tier,                                  -- common | rare | epic | legendary
  slot_index,
  UNIQUE(album_id, slot_index)
)

-- ownership + duplicates. absence of a row = locked.
holding(
  id, sticker_id,
  quantity,                              -- >= 1; >1 means duplicates
  first_acquired_at
)
```

**Notes for the build**

- **Grayscale is never stored.** One colour master per image; locked state is a CSS/canvas filter. This also gives the reveal animation for free.
- **Completion % = holdings-with-quantity≥1 over sticker-count**, computed, never stored. `completed_at` is set the moment it first hits 100%, and gates the export.
- **A random pull is one transaction:** roll tier by odds → pick a sticker in tier → upsert `holding` → append a `random_pull` ledger row. If the pull is a duplicate, the sell action later appends a `duplicate_sale` row; it does not edit the pull.
- **Editing a task's reward** writes `task.reward_coins` and touches nothing historical. Open occurrences read the new value at completion; closed ones keep their snapshot.
- **The weekday mask** is the entire recurrence engine. Occurrences for a viewed window are generated by walking days in range and testing the mask — no stored future, no `RRULE`.
